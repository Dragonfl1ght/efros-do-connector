# Коннектор Efros Defense Operations — установка и запуск

Версия 0.0.4

---

## 1. Что это

Микросервис, который по команде Менеджера задач забирает объекты защиты из Efros Defense Operations (EDO), отбирает нужные поля и отправляет их в адаптер ePlat4m для импорта как Технические средства.

Схема обмена: Efros DO → коннектор → (HTTP) → адаптер e4. Запускает коннектор Менеджер задач по расписанию или вручную.

Без RabbitMQ, без Сервиса агрегации, без собственной базы. Данные транзитные: всё, что получено из EDO, в том же HTTP-запросе преобразуется и уходит в e4.

Java 21, Spring Boot 3.3.5, упакован в Docker-образ на базе `eclipse-temurin:21-jre`.

## 3. Что нужно на хосте

- Docker. Никаких плагинов не требуется.
- Сетевая доступность с хоста коннектора до EDO по HTTPS и до адаптера e4 по HTTPS.
- Сетевая доступность до хоста коннектора со стороны Менеджера задач по порту 8080.
- Учётная запись EDO и учётная запись адаптера e4 (та же, что используют другие коннекторы, например доменная `DEV\edo`).

Сертификаты стендов самоподписанные, коннектор настроен им доверять. Для промышленного контура это нужно пересмотреть — см. раздел 8.

## 4. Установка

### 4.1. Загрузить образ

```
docker load -i efros-do-connector-0.0.4.tar.gz
docker images | grep efros-do-connector
```

### 4.2. Подготовить конфигурацию

В образе не зашито ни одного адреса и ни одного пароля. Всё задаётся снаружи.

```
mkdir -p /opt/efros-do-connector/config
cp application.yml.example /opt/efros-do-connector/config/application.yml
vi /opt/efros-do-connector/config/application.yml
chmod 600 /opt/efros-do-connector/config/application.yml
```

Минимально нужно заполнить шесть значений:

```
connector:
  edo:
    base-url: https://<адрес-EDO>
    login: <учётная-запись-EDO>
    password: '<пароль>'
  e4:
    base-url: https://<адрес-адаптера-e4>
    login: 'DEV\<учётная-запись>'
    password: '<пароль>'
    read-timeout: 120s
```

Адрес адаптера указывается без пути — пути `/api/getToken` и `/api/v1/import/Hardware` коннектор добавляет сам.

Значения, содержащие символы `$`, `*`, `\` или пробелы, обязательно в одинарных кавычках — иначе YAML истолкует их по-своему. Например `'$Qwerty123'`, `'DEV\user'`, `'Passw*rd'`.

`read-timeout: 120s` для e4 обязателен: адаптер обрабатывает импорт долго, на стенде 1869 ТС заняли 91–97 секунд. Значение по умолчанию (30 секунд) для этого мало.

### 4.3. Запустить

```
docker run -d --name efros-do-connector --restart unless-stopped -p 8080:8080 \
  -v /opt/efros-do-connector/config:/app/config \
  efros-do-connector:0.0.4
```

Параметр `--restart unless-stopped` обязателен: иначе после перезагрузки хоста контейнер не поднимется, и Менеджер задач в ближайший запуск по расписанию получит «сервис недоступен».

## 5. Проверка

### 5.1. Сервис поднялся

```
docker logs efros-do-connector | tail -20
```

Ожидаемо: `Started EfrosDoConnectorApplication in N seconds`.

Если вместо этого `Не задана обязательная настройка ...` — конфигурация не подхватилась или в ней не хватает значения. Проверить, что файл виден внутри контейнера:

```
docker exec efros-do-connector ls -l /app/config/
```

Файл должен называться ровно `application.yml` и лежать в каталоге `/app/config/`.

### 5.2. Прогон вручную

```
curl -s -X POST http://localhost:8080/api/integration/launch \
  -H 'Content-Type: application/json' \
  -d '{"integration":{"taskGuid":"test","parameters":null}}'
```

Ответ приходит после окончания импорта — при паре тысяч объектов это 1,5–2 минуты. Успешный ответ:

```
{"accept":true,"condition":{"status":"running"}}
```

Что происходило внутри — в логах:

```
docker logs efros-do-connector 2>&1 | grep -E "EDO|e4|Задача"
```

Пример с тестового стенда:

```
Логин в EDO успешен
EDO вернул 1888 записей
После фильтра осталось 1869 ТС, отправляем в e4
Токен адаптера e4 получен
Адаптер e4 ответил: "Импорт завершен успешно"
Задача test завершена: получено из EDO 1888, отправлено в e4 1869
```

## 6. Настройки

Три источника, каждый следующий перекрывает предыдущий:

- Значения по умолчанию внутри образа — только порт, таймауты и уровень логов.
- Файл `/app/config/application.yml` — основной способ.
- Переменные окружения — удобны для паролей, чтобы не держать их в файле.

Имя переменной выводится из имени настройки механически: верхний регистр, точки и дефисы заменяются на подчёркивания.

| Настройка | Переменная окружения | По умолчанию | Обязательна |
|-----------|---------------------|--------------|-------------|
| `server.port` | `SERVER_PORT` | 8080 | нет |
| `connector.edo.base-url` | `CONNECTOR_EDO_BASE_URL` | — | да |
| `connector.edo.login` | `CONNECTOR_EDO_LOGIN` | — | да |
| `connector.edo.password` | `CONNECTOR_EDO_PASSWORD` | — | да |
| `connector.edo.connect-timeout` | `CONNECTOR_EDO_CONNECT_TIMEOUT` | 5s | нет |
| `connector.edo.read-timeout` | `CONNECTOR_EDO_READ_TIMEOUT` | 30s | нет |
| `connector.e4.base-url` | `CONNECTOR_E4_BASE_URL` | — | да |
| `connector.e4.login` | `CONNECTOR_E4_LOGIN` | — | да |
| `connector.e4.password` | `CONNECTOR_E4_PASSWORD` | — | да |
| `connector.e4.connect-timeout` | `CONNECTOR_E4_CONNECT_TIMEOUT` | 5s | нет |
| `connector.e4.read-timeout` | `CONNECTOR_E4_READ_TIMEOUT` | 30s | задать 120s |

Если обязательная настройка не задана, контейнер не стартует и пишет в лог, какой именно не хватает. Это сделано намеренно: иначе ошибка конфигурации всплыла бы позже и невнятно — как ответ 502 Менеджеру задач.

Пример запуска с паролями через окружение:

```
docker run -d --name efros-do-connector --restart unless-stopped -p 8080:8080 \
  -v /opt/efros-do-connector/config:/app/config \
  -e CONNECTOR_EDO_PASSWORD='...' \
  -e CONNECTOR_E4_PASSWORD='...' \
  efros-do-connector:0.0.4
```

Чтобы поднять подробность логов до DEBUG (видны все HTTP-вызовы), достаточно поправить файл конфигурации и перезапустить контейнер — пересобирать образ не нужно:

```
logging:
  level:
    ru.company.connector.efrosdo: DEBUG
```

## 8. Особенности и ограничения

**Синхронная обработка.** Менеджер задач ждёт ответа на вызов коннектора, пока не закончится импорт. На тестовом стенде весь прогон для 1869 ТС занимает около 95 секунд. **Таймаут Менеджера задач на вызов коннектора должен быть больше** — рекомендуется не меньше 180 секунд, при большем числе объектов — пропорционально больше. Если ТМ не дождётся ответа, он пометит задачу ошибкой, хотя импорт при этом пройдёт.

**Повторы при ошибке.** Если коннектор вернул ошибку, Менеджер задач сам повторяет запуск с интервалом 20 секунд — на стенде три повтора при ручном запуске и пять при запуске по расписанию. Повторный импорт безопасен: записи в e4 обновляются по GUID объекта, а не создаются заново.

**Токены.** Токены EDO и адаптера e4 кешируются между запусками и обновляются автоматически, когда истекают: EDO в этом случае отвечает 401, адаптер — 403 «Ошибка авторизации». Перезапускать контейнер не нужно.

**Статус в ТМ.** Уведомления о смене статуса коннектор не отправляет, поэтому после прогона ТМ продолжает показывать его в состоянии `Running`.

**Совместимость с EDO.** Для выгрузки используется метод `GetListSoHierarchy`. В свежих версиях EDO он помечен как устаревший, но работает; выбран ради совместимости с версией 2.13. На стенде версии 2.52 проверен; наличие метода в конкретной установке EDO стоит проверить до развёртывания:

```
TOKEN=$(curl -k -s -X POST https://<адрес-EDO>/api/identity/Auth/LoginByPassword \
  -H 'Content-Type: application/json' \
  -d '{"userName":"<логин>","password":"<пароль>"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["token"]["accessToken"])')

curl -k -s -X POST https://<адрес-EDO>/api/v1/SecurityObject/GetListSoHierarchy \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{}' | head -c 1000
```

Метод на месте, если вернулся JSON-массив с полями `children` и `ciFeatures`. Если первая команда упала — в этой версии EDO отличается и путь логина, это нужно выяснить до развёртывания.

**TLS.** Оба клиента настроены доверять любым сертификатам, потому что стенды работают на самоподписанных. Для промышленного контура проверку нужно вернуть, добавив корневой сертификат в доверенные.

## 9. Диагностика

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Контейнер не стартует, в логе «Не задана обязательная настройка» | Конфигурация не подхватилась или в ней не хватает значения | Выполнить `docker exec efros-do-connector ls -l /app/config/`, сверить файл с шаблоном |
| В логе «EDO отклонил LoginByPassword: HTTP 401» | Неверные учётные данные EDO | Проверить `connector.edo.login` и `connector.edo.password` |
| В логе «Адаптер e4 отклонил getToken» | Неверные учётные данные адаптера | Проверить `connector.e4.login` и `connector.e4.password`, логин — в одинарных кавычках |
| В логе «Адаптер e4 отклонил токен (HTTP 403)», затем «Импорт завершен успешно» | Истёк токен адаптера | Ничего: коннектор сам получил новый токен и повторил импорт |
| Ответ 502 и `403 Forbidden: "Ошибка авторизации"` от адаптера | Адаптер не принимает и свежий токен — у учётной записи нет прав на импорт | Проверить права учётной записи `connector.e4.login` в ePlat4m |
| Ответ 502 и `Read timed out` | Адаптер не уложился в таймаут | Увеличить `connector.e4.read-timeout` и таймаут ТМ на вызов коннектора |
| Ответ 502 и `502 Bad Gateway` от адаптера | Адаптер временно недоступен | ТМ повторит запуск сам; если повторяется постоянно — проверить состояние адаптера |
| В ответ 502 и `I/O error ... UnknownHostException` | Адрес недоступен с хоста коннектора | Проверить сетевую доступность и адрес в конфигурации |
| ТМ сообщает, что сервис недоступен | Контейнер не запущен, закрыт порт или в регистрации указан не тот адрес | Проверить `docker ps` и поле `location.address` в регистрации |

Полный лог:

```
docker logs efros-do-connector 2>&1 | tail -100
```
